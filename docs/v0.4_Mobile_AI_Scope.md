# ETHAN INVEST TRADER
## v0.4：移动 PWA + AI 决策服务；账户手动维护；PC 研究入口归入 InvestLab

更新日期：2026-11-15  
文档性质：开发范围、产品规则和验收基线。本文不是已部署软件、已完成回测或已证明收益的说明。

## 1. 本次正式决定

第一期只交付 ETHAN INVEST TRADER 的移动 PWA，以及为其提供数据、计算、AI 分析、通知和记录的后台。

不连接 Schwab，不注册或申请 Schwab 开发者权限，不保存券商密码、账户号码或令牌，不读取券商网页，不使用浏览器自动化访问券商。所有下单、改单、撤单和实际交易确认都由用户在 Schwab 官方 App／网页完成。

账户状态和成交由用户手动录入。软件获取的市场行情与用户录入的账户信息具有不同来源和时间，必须分别展示。

PC 的详细分析、参数研究、历史回测和完整复盘界面，后续放入既有 InvestLab 规划，不再开发另一套独立的 ETHAN INVEST TRADER PC 工作台。移动版所需的基础设置、账户初始化、建议查看和记录必须能在手机独立完成，不能等待 PC 模块才能使用。

本文件覆盖旧版冲突要求：

- v0.1/v0.2 的自动执行、交易授权和券商下单模块继续取消。
- v0.3 的只读 Schwab 接入、OAuth、令牌维护和券商成交回读取消。
- v0.3 的 PC/PWA 同期开发改为移动优先，InvestLab PC 后续复用。
- AI 从后期摘要功能调整为首版核心，但必须同时交付数据核验、规则检查和建议效果记录。

## 2. 产品目标与证据边界

目标：在用户设定的资金、风险、持仓周期和操作约束下，辅助 TQQQ 交易决策，并留下可检验的记录，判断 AI 是否提高净收益或改善风险与资金占用。

首版不是行情看板加聊天框，也不是自动交易系统。主要输出是有依据、有反证、有有效条件的建议卡。

不得承诺提高收益，不得预填未经计算的年化、胜率、收益概率。账户信息是用户确认的记录，不是券商认证结果。工程功能验收与投资效果评估必须分开。

## 3. 产品与服务分工

| 组成 | 这一期 | 后续 |
|---|---|---|
| ETHAN INVEST TRADER PWA | 决策、持仓、成交录入、简版复盘、设置、通知 | 根据实际使用优化 |
| 共用后台 | 行情、手动账本、计算、AI 建议、检查、通知、审计 | 继续服务两端 |
| InvestLab PC | 不重做桌面工作台；只预留接口与权限设计 | 加入私人交易研究模块和完整评估界面 |
| Schwab 官方客户端 | 用户自行核查资金并交易 | 不由本系统控制 |

两端共享同一份权威账户记录、策略版本、建议 ID、来源快照和评估记录，不各自维护独立账本，也不各自生成互相矛盾的“当前建议”。AI 服务是独立的逻辑边界，不要求第一版拆成多个物理服务或微服务。

InvestLab 公共学习内容与私人交易数据必须隔离。私人 API 必须鉴权，禁止静态导出、公共缓存或索引账户数据；公共文章不应获得用户账本访问权。

## 4. 移动端信息架构

底部四个入口：决策、持仓、复盘、设置。“记录成交”作为常驻快捷入口。

### 4.1 决策首页

优先展示当前建议及其有效状态，再展示简洁持仓摘要，不把收益大数字或泛化聊天框置于核心。

每张建议卡至少包含：

- 建议类别：等待、按计划考虑首次买入、按计划考虑补仓、按计划止盈、需要重新评估、信息不足。
- 针对的周期与档位；首次入场前可关联计划 ID，不伪造已经持仓的周期。
- 参考报价、报价时点、行情延迟/质量状态。
- 一句话理由、支持依据、主要反证、最重要风险。
- 计划金额或数量上限；账户状态未经核实则不显示具体新增买入数量。
- 操作后假设的持仓、现金和成本；与已发生事实明确分开。
- 有效期限、适用条件、失效条件、建议生成时间。
- 账户快照版本、策略版本、来源入口和待核实事项。

允许的动作：查看证据、围绕当前建议追问、已查看、忽略、稍后提醒、核实账户、记录实际成交。

禁止的动作和文案：确认下单、批准后自动交易、自动平仓成功。可以提示用户自行打开 Schwab，但不假定有支持传递订单参数的券商深链。

### 4.2 持仓页与账户更新弹窗

默认字段：

| 字段 | 定义 |
|---|---|
| 策略持仓股数 | 仅属于当前策略的 TQQQ 数量 |
| 平均持仓成本 | 美元/股；记录是实际成交推算还是抄录券商展示值 |
| 策略现金总额 | 本策略所有现金，包括未结算款；不含 TQQQ 市值 |
| 已结算且未占用现金 | 可用于新增建议的核实金额，是现金总额的一部分，不相加 |
| 挂单状态 | 无/有/不确定；有则展开买卖方向、剩余数量、价格、有效期、部分成交状态 |
| 用户核实时间 | 实际查看券商并确认这些信息的时间，不是页面刷新时间 |

空仓允许股数为零；未知与零分开。现金字段必须满足一致性检查，不能用模糊的 buying power 替代已结算现金。已扣除挂单占款的可用金额不得再次扣减同一笔挂单。

首次接入已有持仓时，条件展开：首次买入日期、首次实际成交锚点、已执行档位、本轮预算、持仓是否涉及未结算资金买入、是否排除长期仓位。缺少锚点或历史时标记不完整，不根据均价猜测阶梯。

当前市场报价由行情源提供，不让用户随市场波动重填。当前估算权益 = 策略持仓数量 × 指定报价 + 策略现金总额；未知数据使该指标不完整时必须提示。

### 4.3 记录成交

字段：方向、实际成交时间、成交数量、实际成交均价、费用（可未知）、所属周期/档位、对应建议（可选自主交易）。

部分成交只记录已成交部分。保存后展示推算状态，由用户核对；该状态标为“据手动成交记录推算”，不能显示“已与券商同步”。

同一笔记录重试不得重复计账。关联建议只是用户报告的采用关系，不证明该建议造成收益。不能把已查看、已计划或已挂单当成成交。

提供资金增加/减少、分红、拆股和纠错记录。手动覆盖账户快照时，生成可追溯的对账调整，不将覆盖值与历史成交重复相加；未解释差异不得计入投资盈利。

### 4.4 简版复盘

首版显示：建议记录、用户实际录入的成交、采纳/忽略/过期状态、权益与资金占用摘要、费用完整性、数据缺口。

记录亏损、未结束周期、未采纳建议和错失机会，不只展示已止盈的交易。区分用户报告结果、假设模拟结果、未能计算结果。

详细参数对照、收益分布和大规模回测界面放入 InvestLab 后续阶段；这不意味着首期可以缺失原始建议和账户记录。

### 4.5 设置

手机可独立设置策略参数、资金和仓位上限、现金储备、复核期限、账户类型（允许未知）、操作时段、北京时间显示、通知级别、金额遮罩、主题和登录安全。

精细布局自定义不是首期重点。数据过期、账户未核对、来源不可用等提示不能隐藏。

## 5. AI 服务的最小完整链路

获取市场证据 + 读取用户账户快照 → 确定性计算 → AI 比较行动方案 → 规则检查 → 保存建议与输入 → 推送和展示 → 收集用户反馈/手动成交 → 后续评价。

### 5.1 数据与计算

最少需要核实可用的 TQQQ 行情与历史价格；QQQ 用于市场背景。事件和新闻只有在能获得可核实来源、发布时间和事件时间时才进入证据包。

接入行情源前检查覆盖、报价延迟、历史复权、使用许可、频率限制和费用。免费、实时、长期分钟历史均不能预设成立。不存在合格数据源时用明确标注的演示模式，不发布实时买卖建议。

成本、现金、仓位、回撤、趋势、补仓阶梯和止盈数学由程序计算，禁止用语言模型的猜测替代。

数据源与模型使用适配器，具体供应商和型号在接入测试时核实，不根据未验证的名称、价格或赠送额度锁定实现。

### 5.2 第一版 AI 的决策范围

固定并版本化机械参数 L、D、N、Y、Z 和单轮预算。此前讨论的 20 日、5% 首次回撤、5 档、5% 间距、4% 止盈仅是候选研究值，不是已验证的默认盈利方案。

AI 第一版主要比较：当机械买入条件成立时，按计划行动还是暂缓；解释市场风险及已有仓位的影响。

既定止盈目标由程序计算并提醒。AI 可以提出另行研究的退出方案，但不能在聊天中悄悄修改当前目标、放宽预算或把短线持仓无限转为长期持有。

首版允许信息不足或证据冲突时不给出具体买卖数量。等待建议的机会成本同样记录。

### 5.3 输出与检查

建议使用固定结构；事实引用只能来自本次证据包中有效的来源 ID，保存原始证据或可审查摘要。格式正确不代表事实或预测正确，必须另做检查。

检查金额、数量、预算、挂单冲突、数据新鲜度、策略版本和价格有效范围。错误输出不直接展示为可执行建议；保留失败原因和受影响范围。

新闻、网页和用户提供的文本作为不可信资料，不能改变系统权限或触发任意工具。AI 不拿服务密钥，不访问券商，不直接修改账户账本。

未经校准不输出精确获利概率。区分事实可信度、证据一致性和统计获利概率，不用“信心 90%”替代实证。

追问绑定建议 ID 和输入快照；涉及现在行情时重新获取证据、生成新版本，不能一边使用旧数据一边声称实时。

## 6. 新鲜度与建议生命周期

展示至少四个时间：行情时间、账户核实时间、建议生成时间、后台任务最后成功时间。

建议状态包括：有效、待核对账户、已过期、被新建议替代、数据失效、用户忽略、已关联手动成交。每次更改保留事件记录，不改写原判断。

用户新增成交、调整资金或修改策略后，依赖旧状态的建议立即作废或标记待复核。新行情不能自动更新账户核实时间。

每个交易时段首次给出具体金额前，要求用户确认账户状态，除非该时段已经完成核实且未报告变化；这仍不证明用户没有漏记交易。关键建议应继续显示“操作前在 Schwab 核对”。

过期账户仍可收到市场观察提醒，但不把数量、成本和资金假设伪装成实时准确值。挂单状态未知时，不重复建议使用相关资金或股数。

## 7. 通知与运行节奏

初版采用规则检查与 AI 分析分频。以下是可修改的工程目标，不是已经验证的最佳交易频率：

- 正常交易时段价格与规则检查目标为每 5 分钟，取决于行情许可和调度验收。
- AI 在首次有效信号、关键市场证据变化、用户更新账户或主动请求时运行；没有新信息不反复生成同一段分析。
- 可配置低频市场摘要和收盘复盘。普通时段不为没有变化的建议反复推送。
- 按周期、档位、账户版本和建议类型去重；价格附近来回波动设置冷却与重新触发条件。

通知默认隐藏金额和股数，详情登录后查看。明确区分服务端已生成、已尝试发送、用户已查看；不能把推送服务接受请求当成用户已经收到或读到。

手机锁屏、后台、离线、重新联网和用户日常网络是验收项目。服务器停机、网络问题和通知权限关闭都可能导致失效；通知不是止盈保障。

后台关闭后恢复，只提示当前仍有效状态，不补发过期交易机会。暂停提醒只暂停消息，不影响 Schwab 的任何持仓或挂单。

## 8. 从首版开始记录 AI 的价值

保留三类后续可比较的记录：机械基准方案、AI 建议方案、用户手动录入的实际操作。买入持有可作额外参照，但不同风险暴露应解释。

机械与 AI 的模拟使用同样初始条件、相同资金和结算约束、同样成本假设，并预先明确人工延迟、有效价格和未成交的处理。没有足够粒度的行情时，不推断理想成交先后顺序。

首期必须交付建议和输入的完整日志、候选动作、反证、采纳状态、后续评估任务记录。完整的收益归因和概率分布可以后做；缺少证据时不显示虚假的评估结果。

对账户有资金流入流出的情况，不把余额增加直接当作收益；采用明确的收益口径并说明费用/税务是否计入。无法重建历史时从明确基准日开始，不编造历史。

当前模型回放历史可能包含对后续事件的知识；历史 AI 回测不能直接当作无泄漏证据。前瞻记录作为重要证据，仍需足够样本和跨市场环境检验。不得以几次正确建议宣称模型有效。

## 9. 技术与部署边界

建议延续 Next.js + TypeScript 作为移动 PWA 和轻量接口的实现候选，页面部署在 Vercel；后台模块按共享服务组织，持久数据放入数据库，任务执行交给满足实际频率与超时要求的服务。

这是一项架构建议，不代表当前账户的免费额度或平台限制已经核实。部署前验证定时任务频率、最大执行时间、失败重试、账单和使用地区要求。不预设免费计划满足盘中检查需求，不先购买 VPS；确有长任务或托管限制时再选独立 worker。

初期不强制新增 FastAPI、Redis、Kubernetes、多代理编排或微服务。后续复杂研究可通过单独离线任务或研究 worker 完成。

建议的逻辑模块：

| 模块 | 责任 |
|---|---|
| 身份与设置 | 私人访问、会话、预算、通知设置 |
| 手动账本 | 账户快照、成交、资金事件、核对及版本控制 |
| 市场证据 | 行情、历史、事件、来源时间、质量状态 |
| 规则计算 | 指标、档位、数学计算、可选行动与约束 |
| AI 分析 | 证据整合、行动比较、反证、结构化建议 |
| 通知 | 去重、有效期、推送、收件箱 |
| 评估 | 历史输入留档、基准、未来结果、数据缺口 |

## 10. 留给 InvestLab 的接口与核心对象

接口由同一服务维护，PWA 与未来 InvestLab 私人模块都使用身份认证后调用的版本化 API，不直接访问数据库。

建议查询/写入语义：

- 读取/新增/核对账户快照。
- 新增成交与资金事件、纠错和历史版本查询。
- 保存和发布策略版本；不会生成券商订单。
- 请求分析、读取任务状态、查询建议、记录查看/忽略/成交关联。
- 读取市场证据、通知收件箱、系统健康与简版评估。
- 管理通知订阅、费用预算与数据导出/删除。

核心对象：AccountSnapshot、TradeRecord、CashEvent、ManualOrderNote、StrategyVersion、Cycle、MarketEvidence、AnalysisRun、Recommendation、RecommendationEvent、EvaluationRecord、Notification、AuditEvent。

所有修改记录有唯一请求 ID 和期望版本，防止双击重复与多设备覆盖。时间以 UTC 存储，界面默认北京时间，市场日期按正确交易日历处理。货币和数量使用明确精度，不靠模型自然语言计算。

AI Key、数据 Key、推送服务秘密只保存在受保护服务端；不进入前端构建、PWA 缓存或公共日志。公开内容与私人 API 使用严格权限边界；服务工作线程不静默重放过期写入。

## 11. 开发顺序与可见交付

| 阶段 | 交付 | 验收门槛 |
|---|---|---|
| A 账户与证据基础 | 手动表单、持仓页、成交记录、身份认证、一个经过核实的数据适配器 | 账户计算一致；数据新旧和来源可见；无券商凭据 |
| B 最小 AI 决策链 | 固定规则计算、真实证据包、AI 建议卡、依据/反证、建议留档 | 数据不足会降级；数字和预算检查通过；手机能看完整判断 |
| C 推送与日常可用性 | PWA 安装体验、后台任务、通知去重、有效期、日终摘要 | 关闭页面仍运行；设备实测；不会重发过期建议 |
| D 首版评价闭环 | 建议/成交关联、机械对照记录、基本权益与数据缺口展示 | 未成交不当成交，亏损与忽略建议不遗漏，无伪造收益 |
| 后续 InvestLab | 私人 PC 研究、完整图表、参数比较、回测与评估 | 复用同一账本与建议版本；不产生第二份真实状态 |

A/B 构成一条尽早可用的纵向链路，不等全部界面装饰完成才接 AI。缺少 B 或 D 不能把首版宣称为“已具备可信投资效果”的 AI 系统。

## 12. 需要用户完成的环节

首次：确认策略资金与基本参数；填写现有持仓和现金；选择通知时段；安装 PWA 并授权通知；在自己控制的平台配置必要的数据/AI 服务凭据和费用预算。

日常：账户发生变化时记录实际成交、挂单和资金变化；核对状态时确认无变化；阅读建议并自行在 Schwab 决定是否交易。

不再需要：Schwab API 申请、美国开发者电话号码、券商 OAuth、券商令牌续期、任何自动交易授权。

AI 与行情服务自身的可用地区、使用条款和费用仍要单独核实，取消 Schwab 接口不自动解决其他供应商的接入要求。

## 13. 首版必测场景

1. 不存在 Schwab 连接、下单、撤单、自动登录或抓取账户的代码路径。
2. 零持仓与未知成本不同；未知现金不默认零；两种现金口径不相加、不重复扣占款。
3. 成交重复提交不重复计账；快照覆盖与成交历史不会重复相加。
4. 挂单、部分成交、已查看建议与真实成交分别记录。
5. 缺少本轮锚点或长期持仓归属不明时，不猜测补仓和全部卖出数量。
6. 报价新、账户旧时，仍显示账户过期并限制数量建议。
7. AI 生成时用户修改账户，发布前版本检查阻止旧建议作为当前建议展示。
8. 来源不可用、模型拒绝/超时、格式错误、预算耗尽均有清楚降级；不伪造分析。
9. AI 引用不存在的来源、超预算数量或无证据概率会被阻止或标记，不能直接推送。
10. 模型和外部网页不能修改账本、策略或权限，也不能读服务密钥。
11. 同类提醒去重；用户离线后的过期提醒不重发；推送接受不视为已读。
12. 提醒暂停不被描述为交易暂停；无任何已经替用户止盈的暗示。
13. 账户和建议日志能导出；资金流、费用未知与不可重建历史在评价中明确显示。
14. 时间、节假日和拆股处理不产生虚假回撤或加仓信号。
15. 后续 InvestLab 只能通过有权限的接口读取私人数据，公开页面和缓存不泄露。

## 14. 第一版完成的定义

用户可以只用手机完成：初始化账户 → 获取有来源、有反证、有有效条件的 AI 建议 → 在 Schwab 自行交易 → 回来记录成交 → 更新下一步建议 → 查看完整建议历史和初步效果记录。

不以接通一次模型 API、做出漂亮聊天页面或演示几次正确预测作为完成标准。产品应帮助用户建立基于记录的信任，而不是制造未经检验的确定感。
